# СтройКрой — приложение для построения выкроек одежды

Методика: **ЕМКО СЭВ** («Единая методика конструирования одежды СЭВ»,
Том 1, Теоретические основы). Источник формул — таблица 7 (СОКО) и
таблицы 2–3 (размерные признаки) того же тома:
https://studfile.net/preview/8697497/ (страницы 1–7 дают всё, что
использовано в движке).

## Структура монорепозитория

```
packages/
  pattern-engine/    общий движок построения выкройки (TypeScript, без UI)
apps/
  studio/            десктоп-приложение разработчика (Tauri), офлайн,
                     полный доступ к формулам/прибавкам/точкам
  client-site/       веб-сайт для клиентов (Next.js), только форма
                     мерок → готовая выкройка, без внутренней кухни
```

Оба приложения используют один и тот же `pattern-engine` — формулу
меняем в одном месте, обновление попадает и в студию, и на сайт.

## Как запустить (на своей машине, нужен интернет для первой установки)

```bash
cd E:\sapr\stroykroy    # или в любую другую папку, куда распаковали архив
npm install            # поставит зависимости для всех пакетов сразу
npm run engine:test    # проверка движка
npm run studio:dev     # студия разработчика в браузере (без Tauri-обвязки)
npm run site:dev       # клиентский сайт
```

Десктоп-обёртка студии (`npm run studio:tauri`) требует установленный
Rust (https://rustup.rs) — это требование самого Tauri, без него
можно работать с `studio:dev` в обычном браузере на том же компьютере
разработчика (офлайн это тоже обеспечивает, раз сервер локальный).

## Как устроен движок (важно)

Формулы построения — это **данные**, а не код. В
`packages/pattern-engine/src/default-dress-bodice-steps.ts` лежит массив
шагов (`FormulaStep[]`) — ровно по одному на каждую строку таблицы 7
методики. Каждый шаг — текстовая JS-формула, которая может ссылаться на
мерки (`M.rz13`), прибавки (`P.a8`), уже посчитанные числа (`V["id"]`) и
точки (`pt["id"]`). Вычисляет это всё `evalFormulaSteps()` из
`formula-engine.ts` — строго по порядку, с перехватом ошибок на каждом
шаге (один сломанный шаг не валит весь чертёж).

В студии разработчика (`apps/studio`) это редактируется прямо в
интерфейсе — вкладка «Формулы»: список строк, в каждой — id, вид
(число/точка/дуга) и сама формула. Правите текст — чертёж
пересчитывается сразу, без пересборки приложения.

## Статус на сейчас

Реализовано и численно проверено (женская фигура, типовая 164-96-104):
- сетка спинки (11-31-41-51), ширина по линии груди (31-33-35-37)
- нижняя дуга проймы — спинка и перед (через пересечение окружностей)
- горловина спинки (дуга через засечки циркулем)
- вытачка на выпуклость живота, вытачка на выпуклость груди
- вытачка на выпуклость лопаток (раствор на табличный угол β34)

Известные нерешённые шаги (видны прямо в студии, во вкладке «Формулы»,
подсвечены красным, также перечислены в `result.errors`):
- **точка 16** (вершина горловины переда, стр.52) — формула переведена
  в дугу (не вертикальное вычитание), но результат геометрически
  подозрителен (может быть выше линии плеч). Нужен рис. 19 из оригинала.
- **точка 14'** (вытачка на лопатки, стр.31-37) — засечка окружностей
  не сходится ни при каком угле плеча (проверено перебором 0°…80°).
  Похоже, неверно определены точки 32/122 относительно 13/14 — нужен
  рис. 15-16 из оригинала. Из-за этого не строится и верхняя дуга
  проймы спинки (342pp, зависит от 14').

Не реализовано: рукав, капюшон, юбка, брюки — формулы для них есть в
том же источнике (таблица 7 целиком), добавим по необходимости.

Не реализовано: база данных клиентов, роли/аутентификация, экспорт в
PDF/DXF — следующие шаги после того, как сам движок будет полностью
закрыт по спинке+переду.
